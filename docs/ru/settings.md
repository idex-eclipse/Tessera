# Настройки и хранилище

Собственного бэкенда у Tessera нет. Настройки живут в `localStorage` браузера
(синхронная рабочая копия) и **зеркалируются в базе данных Moonraker** принтера, поэтому
переживают смену браузера (см. [Зеркало в Moonraker](#зеркало-в-moonraker)).
Схема версионируется префиксом `mpu:v2:`.

## Ключи localStorage

| Ключ | Содержимое |
|---|---|
| `mpu:v2:printers` | `[{ id, name, url }]` — реестр принтеров |
| `mpu:v2:activePrinter` | `id` активного принтера |
| `mpu:v2:plugins` | remote-плагины: `[{ manifestUrl, enabled, printerIds, source, installedVersion }]` |
| `mpu:v2:ui` | UI устройства: тема, язык, `dir`, размеры панелей, фон, акцент, fleet, переопределения hotkeys |
| `mpu:v2:custom-font` | один загруженный шрифт WOFF2, WOFF, TTF или OTF (до 1 МиБ), имя и data URL; синхронизируется отдельно |
| `mpu:v2:editor-colors` | цвета подсветки в редакторе конфигов: `{ v: 1, light: { <токен>: '#rrggbb' }, dark: { … } }` — только изменённые пользователем токены; применяются как CSS-переменные `--tok-<токен>` (шапка редактора → кнопка настроек) |
| `mpu:v2:settings:<printerId>` | настройки принтера: видимость страниц, провайдеры виджетов, раскладка дашборда, чипы |
| `mpu:v2:settings:GLOBAL` | то же, общее для всех принтеров (если включена синхронизация дашборда; см. ниже) |
| `mpu:v2:plugin-settings:<printerId>:<pluginId>` | настройки плагина для принтера (`api.settings`) |
| `mpu:v2:plugin-settings:GLOBAL:<pluginId>` | настройки плагина, общие на устройство (sync включён) |
| `mpu:v2:settingsSync` | `{ plugins: { <pluginId>: boolean }, dashboard: boolean }` — флаги синхронизации |
| `mpu:v2:auth:<printerId>` | токен авторизации Moonraker для принтера |

Core-плагины в `mpu:v2:plugins` **не записываются**: они вшиты в бандл хоста.

### `mpu:v2:plugins`

| Поле | Описание |
|---|---|
| `manifestUrl` | URL манифеста (абсолютный или относительный к origin хоста) |
| `enabled` | включён ли плагин |
| `printerIds` | пусто — на всех принтерах; иначе только на перечисленных (применяется к чипам и hotkeys) |
| `source` | `'catalog'` или `'url'` — откуда установлен |
| `installedVersion` | версия на момент установки (для бейджа «доступно обновление») |

### `mpu:v2:ui`

```ts
interface UiState {
  theme: 'light' | 'dark';
  highContrast: boolean;            // независимо от светлой/тёмной темы
  fontScale: number;                 // 80–150 с шагом 10; по умолчанию 100
  letterSpacing: number;             // дополнительный интервал: 0–12% от em, шаг 2
  glyphWidth: number;                // оптическое расширение контура: 0–6% от em, шаг 1
  locale: string;
  dir: 'ltr' | 'rtl';
  sidebarCollapsed: boolean;
  sidebarWidth: number;
  rightPanelCollapsed: boolean;
  rightPanelWidth: number;
  bgImage: string | null;          // data-URL пользовательского фона
  accent: string | null;           // акцентный цвет, '#rrggbb'
  fleetOpen?: boolean;
  fleetPanels: { pluginId: string; contributionId: string; visible: boolean }[];
  fleetPanelsCustomized: boolean;
  hotkeyOverrides: Record<string, string | null>;   // "<pluginId>:<id>" → комбинация | null
}
```

Шрифт хранится отдельно от `ui`, поэтому смена внешнего вида не пересылает его
заново. Файл входит в экспорт/импорт настроек и синхронизируется через Moonraker;
без Moonraker остаётся доступным в этом браузере. Для кода и G-code сохраняется
моноширинный шрифт.

### `mpu:v2:settings:<printerId>`

```ts
interface PrinterSettingsState {
  pages: Record<string, boolean>;               // видимость страниц (по id страницы); нет ключа = видна
  widgetProviders: Record<string, string>;      // type → provider (пишется, если провайдеров > 1)
  dashboardLayout: DashboardWidgetLayoutItem[]; // { instanceId, type, provider, x, y, w, h }
  dashboardLayoutCustomized?: boolean;          // false → «виртуальный» стандартный layout
  quickChips: QuickChipLayoutItem[];            // { instanceId, type, provider, id, label? }
  quickChipsCustomized?: boolean;
  quickChipsLayout: 'grid' | 'scroll';          // широкий дашборд; нет/ошибка → grid
}
```

Пока пользователь не менял раскладку, хост показывает *стандартный* состав
(он не записывается в хранилище и подстраивается под установленные плагины);
первое изменение фиксирует раскладку и ставит флаг `…Customized`. Сброс снимает флаг, и
то же могут сделать отмена или откат в режиме редактирования дашборда, если они возвращают
к стандартному состоянию.
Предпочтение раскладки чипов не зависит от стандартного состава, хранится отдельно для
каждого принтера и входит в историю отмены, повтора и отката редактора.

## Настройки плагина (`api.settings`)

Для плагина это просто хранилище «ключ → JSON-значение» (см.
[plugin-api.md](plugin-api.md#настройки)). Что полезно знать о хранении:

- Один JSON-объект на пару «принтер + плагин» хранится в `localStorage` (и зеркалируется в DB Moonraker).
  Значения должны быть сериализуемы в JSON.
- Запись синхронная, изменения немедленно уведомляют подписчиков `onChange`
  (в том числе другие экземпляры вашего плагина на других поверхностях).
- Хост держит кэш в памяти; ключ кэша, как и ключ хранилища, учитывает режим sync.

### Синхронизация между принтерами (sync)

Settings → Plugins: у каждого плагина есть тумблер **sync** (по умолчанию выключен).

| Режим | Где лежат настройки |
|---|---|
| sync выключен | `mpu:v2:plugin-settings:<printerId>:<pluginId>` — свои на каждый принтер |
| sync включён | `mpu:v2:plugin-settings:GLOBAL:<pluginId>` — одни на все принтеры устройства |

Плагин ничего не знает о режиме: API одинаков. При переключении данные
переносятся так (переключение выполняется на **активном** принтере, и перенос
касается именно его набора):

- **включение** копирует настройки активного принтера в общий набор, но только
  если общий набор ещё пуст (существующие общие настройки не затираются);
- **выключение** записывает общий набор в набор активного принтера (перезаписывая
  его); наборы остальных принтеров остаются, какими были до включения sync.

Подписчики `onChange` получают обновление в момент переключения, без перезагрузки страницы.
О последующих записях узнают только подписки, сделанные после переключения, поэтому
подпишитесь заново, если плагин переключает sync во время работы.

Следствие для разработчика: **всё, что вы пишете в `api.settings`, может оказаться
общим для всех принтеров** (колонки таблицы, сортировки, пользовательские префы). Не
храните там вещи, которые обязаны быть уникальны для принтера (калибровки, URL
конкретной камеры), либо предусмотрите ключи с идентификатором принтера.

Отдельный флаг `dashboard` в `mpu:v2:settingsSync` переводит весь набор настроек принтера
(раскладку дашборда и чипы, а также видимость страниц и провайдеры виджетов) в общий
`mpu:v2:settings:GLOBAL`. В сторе есть `setDashboardSync`, но переключателя в UI пока нет.

### Рекомендации

- Ключи с префиксом области: `columns:page:gcodes`, `sort:widget:history`.
- Версионируйте формат значений, если он может измениться (`{ v: 2, … }`),
  и умейте читать старый.
- Не складывайте в настройки большие данные (картинки, логи): это `localStorage`
  (около 5 МБ на origin на все ключи).
- Значения по умолчанию задавайте при чтении: `get(k) ?? default`.

## Экспорт и импорт

Settings → About / Debug:

- **Export** сохраняет в JSON ключи `mpu:v2:*`, кроме токенов авторизации Moonraker
  (`mpu:v2:auth:*`): после импорта на другом устройстве войдите заново.
- **Import** записывает ключи `mpu:v2:*` из файла в `localStorage` и перезагружает
  страницу; чужие ключи пропускаются.

## Несовместимая схема

При старте хост ищет ключи старых схем (`mpu:v1:*` или `mpu:*` без `v2`). Если
нашёл, показывает диалог «формат настроек изменился»: пользователь экспортирует
старые данные или сбрасывает их. Автоматической миграции нет — вы не получите
старые настройки плагина без повторной настройки.

## Зеркало в Moonraker

Хост копирует синхронизируемые ключи в namespace `tessera` базы Moonraker и забирает
оттуда более новые копии. `localStorage` не заменяется: он остаётся рабочей копией и
запасным вариантом, поэтому без доступного Moonraker всё работает как раньше, а
существующие установки переносятся автоматически (локальные ключи, которых нет в DB,
публикуются при первом запуске).

| Зеркалируется | Остаётся только на устройстве |
|---|---|
| `ui`, `custom-font`, `plugins`, `editor-colors`, `settings:*`, `plugin-settings:*` | `printers`, `activePrinter`, `auth:*` (токены), `deviceId`, `settingsSync`, фоновое изображение (`ui.bgImage`) |

Куда попадает ключ: ключи принтера (`settings:<id>`, `plugin-settings:<id>:*`) — в DB
этого принтера; глобальные (`ui`, `plugins`, наборы `GLOBAL`) — в DB принтера, который
отдаёт страницу (тот же origin, иначе первый принтер). Записи хранятся без локальных id
принтеров, поэтому второй браузер, импортировавший тот же список принтеров, их видит.

Запись в DB (ключ = ключ `mpu:v2` без префикса, `.` записывается как `%2E`, потому что
Moonraker считает точку разделителем пути):

```json
{ "app": "tessera", "kind": "settings", "schema": 2, "key": "mpu:v2:settings:…",
  "rev": 7, "updatedAt": 1767225600000,
  "writer": { "deviceId": "…", "host": "192.168.1.20:8000", "userAgent": "…" },
  "data": { } }
```

`app`/`kind` помечают запись как настройки Tessera; `writer` показывает, какой браузер
её сохранил (браузер не знает собственный IP, а Moonraker его не сообщает, поэтому
пишутся id устройства, хост, по которому открыта страница, и User-Agent).

Правила:

- **Побеждает последняя запись по `rev`.** Перед записью читается удалённый `rev` и
  публикуется `max(удалённый, локальный) + 1`; ещё не отправленная локальная правка не
  перезаписывается более старой удалённой копией.
- Запись откладывается (около 0,5 с) и повторяется, пока Moonraker недоступен.
- У Moonraker нет уведомлений об изменении DB, поэтому другие браузеры подхватывают
  изменения при старте, при фокусе окна и при каждой смене принтера. Новые копии
  применяются на месте (изменённый список плагинов требует перезагрузки страницы, хост
  делает её сам).
- Экспорт/импорт пропускают `deviceId` и служебные данные зеркала; импорт отправляется в
  DB. Записи в namespace без `app: "tessera"` игнорируются.

## Что хост хранит не в localStorage и не в DB Moonraker

Больше ничего. Данные принтеров (файлы, история, температуры) живут в Moonraker/Klipper;
хост не дублирует их и не читает для собственного интерфейса. Fleet-индекс поиска
(теги и имя печатаемого файла, которые публикуют fleet-панели) хранится только в
памяти и нигде не сохраняется.
