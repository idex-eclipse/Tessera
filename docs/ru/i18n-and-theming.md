# Локализация и дизайн-система

## Локализация

### Как плагин поставляет переводы

Модуль `entry` экспортирует именованный `locales` — объект
`{ <locale>: <сообщения> }`. Загрузчик после `import()` сливает его в словарь
хоста (глубоким слиянием):

```ts
export const locales = {
  en: {
    acme: {
      title: 'Hello',
      greeting: 'Active printer: {name}',
      errors: { offline: 'Printer is offline' },
    },
  },
  ru: {
    acme: {
      title: 'Привет',
      greeting: 'Активный принтер: {name}',
      errors: { offline: 'Принтер недоступен' },
    },
  },
};
```

`manifest.locales` — лишь декларация поддерживаемых языков (`["en","ru"]`);
значение имеют только фактические сообщения из `locales`.

Сообщения могут быть **вложенными** объектами (как выше) или **плоскими**
ключами `"acme.title": "…"`. Точное совпадение плоского ключа имеет приоритет,
затем идёт обход по точкам.

### Использование

```ts
api.i18n.t('acme.title');
api.i18n.t('acme.greeting', { name: api.printer.name });   // подстановка {name}
```

`titleKey` у страниц, виджетов, чипов и fleet-панелей — тоже ключи `t`.

### Как ключ находится

Словарь **общий** для хоста и всех плагинов. Для текущей локали ищутся по
очереди:

1. точная локаль (`ru-ru`, регистр и `_`/`-` нормализуются);
2. базовый язык (`ru`), если у локали есть регион;
3. запасная локаль хоста (`en`).

Если ключа нет нигде, `t` возвращает **сам ключ**.

Следствия:

- **Namespace обязателен.** Все ключи плагина должны начинаться с уникального
  префикса (`acme.`), иначе вы перезапишете чужие строки: слияние глубокое и без
  защиты от коллизий.
- Общие строки хоста доступны любому плагину: `common.*` (`add`, `remove`,
  `refresh`, `edit`, `save`, `cancel`, `close`, `retry`, `reset`, `back`,
  `loading`, `error`, `confirm`, `klipperNotReady`, …). Их можно использовать
  без дублирования. Другие ветки хоста (`settings.*`, `dashboard.*`, `nav.*`)
  — внутренние, на их стабильность не рассчитывайте.
- Строки, добавленные плагином, **не удаляются** при выключении/удалении
  плагина до перезагрузки страницы.
- Если плагин не знает язык пользователя, он увидит строки на `en` — всегда
  давайте полный `en`.

### Смена языка и RTL

```ts
const off = api.onLocaleChange((locale, dir) => rerender());
```

Хост выставляет `lang`-подобные атрибуты на `<html>`: `data-locale`, `dir`
(`ltr` | `rtl`). Для RTL используйте **логические** CSS-свойства:
`margin-inline-start`, `padding-inline`, `inset-inline-end`, `text-align: start`,
`border-inline-start` вместо `left/right`.

## Дизайн-система

Все поверхности должны выглядеть как один продукт. Это достигается общими
правилами и CSS-переменными темы, а не подгонкой каждого плагина.

### Тема

Хост ставит на `<html>` атрибут `data-theme="light|dark"`. Переменные
определены для обеих тем. Пользователь может задать **акцентный цвет** — хост
переопределяет `--accent` инлайном на `<html>`; производные цвета пересчитываются
автоматически.

Правило: **в компонентах плагина не используйте hex-цвета.** Только переменные,
иначе плагин сломается на другой теме или с другим акцентом. Для canvas/WebGL
читайте значение переменной в момент отрисовки и перерисовывайтесь по
`onThemeChange`:

```ts
const accent = getComputedStyle(document.documentElement).getPropertyValue('--accent').trim();
```

### Переменные

**Фоны**

| Переменная | Назначение |
|---|---|
| `--bg-app` | фон приложения |
| `--bg-surface` | фон панелей и карточек |
| `--bg-surface-hover` | hover на поверхности (подмешивает акцент) |
| `--bg-surface-hover-no-override` | нейтральный приглушённый фон для кнопок/полей: фиксированный цвет темы, **не** смешивается с акцентом (в отличие от `--bg-surface-hover`) |
| `--bg-surface-active` | выбранный/активный элемент (подмешивает акцент) |
| `--bg-header`, `--bg-sidebar` | шапка и боковая панель (для плагинов обычно не нужны) |
| `--bg-overlay` | затемнение под модальными окнами (бэкдроп) |

**Текст**

`--text-primary`, `--text-secondary`, `--text-muted`, `--text-on-header`,
`--text-on-header-muted`.

**Границы и фокус:** `--border-color`, `--border-focus`.

**Акцент и семантика**

| Переменная | Назначение |
|---|---|
| `--accent` | основной интерактивный цвет (кнопки, активные состояния) |
| `--accent-text` | цвет текста **на** акцентной заливке |
| `--accent-hover`, `--accent-active` | состояния акцентной кнопки |
| `--accent-subtle`, `--accent-subtle-strong` | полупрозрачная акцентная заливка |
| `--accent-ring` | кольцо фокуса |
| `--danger` | ошибка, деструктивное действие |
| `--warning` | предупреждение, «запитано/активно» |
| `--success` | норма, успех |
| `--heat` / `--cool` | тепловая семантика: нагрев / охлаждение |

**Размеры и оформление**

| Группа | Переменные |
|---|---|
| Отступы | `--space-xs` 4px, `--space-sm` 8px, `--space-md` 16px, `--space-lg` 24px, `--space-xl` 32px |
| Радиусы | `--radius-sm` 4px, `--radius-md` 8px, `--radius-lg` 12px |
| Типографика | `--font-family`, `--font-size-sm` (0.925rem), `--font-size-md` (1rem), `--font-size-lg` (1.2rem) |
| Тени | `--shadow-sm`, `--shadow-md`, `--shadow-lg` |
| Переходы | `--transition-fast` (150ms), `--transition-normal` (250ms) |
| Сетка дашборда | `--grid-row-height` (80px) |
| Слои | `--z-plugin-overlays` (60), `--z-right-panel` (30) |

Светлые/тёмные значения лежат в [`host/src/styles/global.css`](../../host/src/styles/global.css).

> Переменные из `:root` живут в одном CSS-пространстве со страницей: Custom
> Element не изолирован Shadow DOM'ом (хост монтирует элемент как есть),
> поэтому глобальные стили хоста применяются и к вашему содержимому. Стилизуйте
> свой компонент с префиксом классов или собственным Shadow DOM, чтобы
> не затрагивать чужое.

### Панельный язык

Базовая единица интерфейса — **панель** (карточка).

- Страница плагина = вертикальный стек панелей. Допустим grid из нескольких
  независимо скроллящихся панелей, если они образуют одну рабочую поверхность.
- **Отдельного большого заголовка страницы нет**: название задаёт пункт боковой
  панели. Внутри страницы — только заголовки панелей.
- Панель: заголовок внутри блока, контентная область, при необходимости footer.
  Фон `--bg-surface`, рамка `--border-color`, радиус `--radius-md`/`--radius-lg`,
  тень по необходимости, типографика хоста.
- **Заголовок панели:** слева название (с `ellipsis`, без переноса), справа
  `headerActions` — кнопки, иконки, переключатели, поиск, refresh. Второстепенные
  действия — иконками; если действий много — основные видны, остальные в меню;
  деструктивные действия — только с подтверждением.
- **Виджет** — уменьшенная страница: тот же язык панели, заголовок внутри карточки
  (его рисует хост), действия в шапке (`headerElement`), плотнее контент.
- **Чип** — не панель, а мини-элемент: слот высотой 80px, ширина по содержимому;
  тело из двух строк (категория сверху — uppercase, приглушённо; ниже — значение);
  слева полоска-индикатор состояния цветом семантики; действие — поповером;
  *missing* — пунктирная рамка и приглушённый текст.
- **Модальные окна** (оверлеи): бэкдроп `--bg-overlay`, диалог — панель.
- Кнопки: акцентная заливка (`--accent` + `--accent-text`) — для главного
  действия, нейтральные (`--bg-surface-hover-no-override`) — для прочих,
  `--danger` — для деструктивных.

### Состояния

Для каждой поверхности продумайте и покажите: загрузку, пусто, ошибку,
*Klippy not ready*, отсутствие связи. Не полагайтесь на то, что хост всё
перекроет: offline-overlay закрывает интерфейс, но ваш элемент остаётся
смонтированным и продолжает получать события.

### Доступность и поведение

- Интерактивные элементы — настоящие `button`/`a`/`input`, а не `div` с `onclick`.
- Видимый фокус (`--accent-ring`/`--border-focus`).
- Не блокируйте скролл страницы и колесо мыши без необходимости.
- Сохраняйте работоспособность при узкой ширине: сетка дашборда схлопывается в
  одну колонку.
