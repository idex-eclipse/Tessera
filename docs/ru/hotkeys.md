# Горячие клавиши

Хост слушает `keydown` на `window` и вызывает обработчики плагинов и собственные
действия навигации. Плагин объявляет горячие клавиши **декларативно**, в
манифесте; пользователь может переназначить или отключить любую из них в
**Settings → Hotkeys**.

## Объявление

```json
{
  "hotkeys": [
    {
      "id": "acme-refresh",
      "scope": "plugin",
      "keys": "Alt+R",
      "handler": "refreshHandler",
      "titleKey": "acme.hotkey.refresh"
    }
  ]
}
```

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | идентификатор внутри плагина |
| `scope` | да | `global`, `dashboard` или `plugin` (см. ниже) |
| `keys` | да | комбинация; должна разбираться (см. «Запись комбинаций») |
| `handler` | да | имя экспорта entry-модуля |
| `titleKey` | нет | i18n-ключ описания для Settings и About |
| `allowInInputs` | нет | срабатывать ли в полях ввода (см. ниже) |

Некорректная запись (неизвестный `scope`, неразбираемые `keys`, пустые поля)
отбрасывается при загрузке с предупреждением в консоль.

Обработчик — экспорт модуля плагина:

```ts
import type { PluginApi } from '@sdk/types';

export async function refreshHandler(api: PluginApi, event: KeyboardEvent): Promise<void> {
  await reloadMyData(api);
}
```

- первый аргумент — `PluginApi` вашего плагина;
- второй — исходный `KeyboardEvent` (`preventDefault()` уже вызван хостом);
- исключения (и отклонённые Promise) логируются хостом и никому не мешают;
- если экспорта с таким именем нет, хост один раз пишет предупреждение и
  клавишу игнорирует.

## Области действия

| `scope` | Когда активна |
|---|---|
| `global` | везде: дашборд, любая страница, Settings |
| `dashboard` | только когда открыт дашборд |
| `plugin` | только на странице **плагина-владельца** |

Дополнительно:

- Пока открыт fleet-режим (он перекрывает main), `dashboard` и `plugin` не
  срабатывают; `global` — срабатывают.
- Клавиши плагина не срабатывают, если плагин не применим к активному принтеру
  (`printerIds` записи плагина).
- Определение «страница плагина»: хост находит владельца страницы по её `id` в
  текущем маршруте.

## Запись комбинаций

Формат: `Модификатор+Модификатор+Клавиша`, регистр не важен.

**Модификаторы:** `Ctrl` (`Control`), `Alt` (`Option`), `Shift`, `Meta`
(`Cmd`, `Command`, `Win`, `Super`) и платформенный **`Mod`** — это `Cmd` на
macOS и `Ctrl` на остальных платформах. Рекомендуется писать `Mod+…` для
кросс-платформенных действий.

**Клавиши:**

- буквы и цифры — `K`, `1` (в том числе с цифрового блока);
- знаки: `/`, `,`, `.`, `;`, `'`, `` ` ``, `-`, `=`, `[`, `]`, `\` — или словами
  `slash`, `comma`, `period`, `semicolon`, `quote`, `backquote`, `minus`,
  `equal`, `plus`;
- именованные: `Escape` (`Esc`), `Enter` (`Return`), `Tab`, `Space`,
  `Backspace`, `Delete` (`Del`), `Home`, `End`, `PageUp`, `PageDown`,
  `ArrowUp` (`Up`), `ArrowDown` (`Down`), `ArrowLeft` (`Left`),
  `ArrowRight` (`Right`), `F1`…`F12`.

Примеры: `F`, `Alt+1`, `Ctrl+Shift+K`, `Mod+/`, `Shift+/`, `Ctrl+ArrowRight`, `Ctrl++`.

Некорректно: пустая строка, только модификаторы (`Ctrl+Shift`), две основные
клавиши (`Ctrl+K+L`), повтор модификатора, пустая часть (`Ctrl++K`).

**Совпадение точное по модификаторам**: `Ctrl+K` не срабатывает при зажатом
`Ctrl+Shift+K`. Одиночные модификаторы события игнорируются.

**Независимость от раскладки.** Буквы, цифры и знаки сопоставляются по
*физической* клавише (`KeyboardEvent.code`), поэтому `Ctrl+K` работает и при
русской раскладке. Именованные клавиши (`F5`, `Escape`, стрелки)
сопоставляются по значению `event.key`.

## Конфликты

Две записи с одинаковой комбинацией (после нормализации) могут быть допустимы
или конфликтовать — в зависимости от областей:

| A \ B | `global` | `dashboard` | `plugin` |
|---|---|---|---|
| `global` | конфликт | конфликт | конфликт |
| `dashboard` | конфликт | конфликт | допустимо |
| `plugin` | конфликт | допустимо | разные плагины — допустимо, один плагин — конфликт |

**Разрешение конфликта — отключение обеих (всех) сторон** с предупреждением в
консоли (`[hotkeys] Conflict on "…": …`). Отключается и тот, кто конфликтует лишь
с одной из нескольких записей. Когда конфликт разрешается (плагин удалён,
пользователь переназначил клавишу), оставшиеся записи оживают сами.

Конфликты считаются по *действующим* комбинациям, то есть уже после переназначений
пользователя. Хостовые клавиши навигации участвуют в проверке наравне с
плагинными: хост не получает приоритета — плагин, занявший `F`, отключит и себя, и
«fleet» (см. ниже).

## Поля ввода

Если фокус в `input`, `textarea`, `select` или `contenteditable`, по умолчанию
срабатывают только комбинации с `Ctrl`, `Alt` или `Meta`. Одиночные клавиши и
`Shift+клавиша` в полях ввода не срабатывают — это нормальный набор текста.

Поле `allowInInputs` переопределяет правило: `false` — не срабатывать в
полях ввода даже с модификатором (нужно для комбинаций, имеющих смысл в тексте:
`Ctrl+стрелки` — переход по словам), `true` — срабатывать всегда.

Хост также не вызывает обработчик, если событие уже обработано
(`defaultPrevented`), на автоповторе (`repeat`) и во время IME-ввода.

## Хостовые клавиши навигации

| Клавиши | Действие |
|---|---|
| `F` | открыть/закрыть fleet-режим |
| `Ctrl+1` … `Ctrl+9` | перейти на дашборд принтера с этим номером (если нет — ничего) |
| `Ctrl+→` | следующий принтер (по кругу) |
| `Ctrl+←` | предыдущий принтер (по кругу) |

Переход закрывает fleet, чтобы результат был виден. `F` и `Ctrl+стрелки` не
срабатывают в полях ввода. Не занимайте эти комбинации в плагинах — иначе обе
стороны отключатся.

Ограничения платформы (хост на них повлиять не может): `Ctrl+1…9` на некоторых
браузерах/ОС забирает браузер (переключение вкладок), а `Ctrl+←/→` на macOS по
умолчанию переключают рабочие столы.

## Переназначение пользователем

Settings → Hotkeys показывает все клавиши хоста и плагинов, сгруппированные по
владельцу. Для каждой можно:

- **Изменить** — нажать новую комбинацию (`Esc` отменяет запись; на время записи
  все хоткеи приостановлены);
- **Выключить / Включить**;
- **Сбросить** к значению из манифеста; «Сбросить все» — для всех.

Переопределения хранятся в `mpu:v2:ui.hotkeyOverrides` (общие на устройство):
ключ `"<pluginId>:<hotkeyId>"` (для хоста — `"@host:<id>"`), значение — новая
комбинация или `null` (отключена). Некорректное значение игнорируется, остаётся
комбинация по умолчанию. Если после переназначения возник конфликт, он
разрешается по общим правилам (обе отключаются), а в Settings у строк появляется
пометка «конфликт: …».

Из этого следует правило для разработчика: **не полагайтесь на то, что ваша
комбинация останется неизменной**. `PluginApi` не сообщает плагину действующую
комбинацию, поэтому не выводите её в интерфейсе плагина как константу
(«нажмите Alt+R»); подсказку пользователю даёт Settings → Hotkeys.

## Рекомендации

- Предпочитайте `scope: 'plugin'` — это наименее конфликтный вариант.
- Действия оверлея (он виден на любой странице) объявляйте как `scope: 'global'` и
  делайте обработчик безопасным no-op, пока оверлей не открыт. Помните, что хост
  вызывает `preventDefault()` до обработчика, поэтому для таких клавиш берите
  комбинации с модификатором (`Alt+…`), чтобы не перехватывать обычный ввод.
- Для кросс-платформенных действий — `Mod+…`.
- Не занимайте системные и браузерные комбинации (`Ctrl+T/W/N/R/L/Tab`,
  `F5`, `F12`, `Alt+←`): события может перехватить браузер раньше страницы.
- Не используйте одиночные буквы в `global`: они не сработают в текстовых полях и
  вероятнее всего конфликтуют с хостом.
- `titleKey` стоит задавать всегда: без него в Settings будет виден только `id`.
- Обработчик должен быть быстрым и идемпотентным; долгие операции запускайте
  и возвращайте Promise, не блокируя поток.
