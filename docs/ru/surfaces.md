# Справочник по поверхностям (вкладам плагинов)

«Поверхность» — место в интерфейсе хоста, куда плагин может подмонтировать свой
Custom Element. Хост владеет самим местом (раскладка, z-порядок, показ/скрытие
контейнера), плагин владеет содержимым.

| Поверхность | Манифест | Где живёт | Кто решает, показывать ли | Remote |
|---|---|---|---|---|
| [Страница](#1-страницы) | `pages[]` | область main, пункт в боковой панели | пользователь (Settings → Pages) | да |
| [Виджет](#2-виджеты) | `widgets[]` | сетка дашборда | пользователь (раскладка дашборда) | да |
| [Баннер](#3-баннеры) | `banners[]` | сверху main, в потоке | **плагин** | да |
| [Оверлей](#4-оверлеи) | `overlays[]` | поверх main и правой панели | **плагин** | да |
| [Чип](#5-чипы-быстрого-доступа) | `chips[]` | полоса под баннерами | пользователь (edit-режим) | да |
| [Fleet-панель](#6-fleet-панели) | `printerPanels[]` | карточка принтера в fleet | пользователь (редактор панелей) | да |
| [Hotkey](#7-горячие-клавиши) | `hotkeys[]` | глобально | пользователь (Settings → Hotkeys) | да |
| Правая панель | `rightPanel` | колонка справа | — | **нет** (только `@core/system`) |

Слои сверху вниз:

```
offline-overlay       — статус соединения (только хост)
оверлеи плагинов      — модальные окна
правая панель         — колонка справа
баннеры               — в потоке сверху main (раздвигают контент)
полоса чипов          — в потоке под баннерами
main-контент          — дашборд / страница плагина / Settings
```

## Общие правила для всех поверхностей

1. **Один вклад — один Custom Element.** Поле `element` — тег, который плагин
   зарегистрировал в своём модуле.
2. **Хост передаёт `api` и `params`** свойствами (см. [plugin-development.md](plugin-development.md#4-контракт-custom-element)).
3. **Бизнес-данные хост не читает.** Всё, что поверхность показывает, она берёт
   из Moonraker сама.
4. **Единый визуальный язык** — панель (см. [i18n-and-theming.md](i18n-and-theming.md#панельный-язык)).
5. Хост монтирует элемент, когда поверхность появляется на экране, и размонтирует,
   когда исчезает. Освобождайте подписки в `disconnectedCallback`.
6. Для страниц и виджетов `id`/`type` считаются глобальными именами — используйте
   префикс плагина.

## 1. Страницы

```json
{
  "pages": [
    { "id": "acme-hello", "titleKey": "hello.title", "icon": "file",
      "element": "acme-hello-page" }
  ]
}
```

| Поле | Описание |
|---|---|
| `id` | идентификатор страницы; **глобально уникален** (см. ниже) |
| `titleKey` | i18n-ключ названия в боковой панели |
| `icon` | имя встроенной иконки хоста (по умолчанию «файл») |
| `iconSvg` | своя иконка: строка SVG. Можно не писать в манифесте, а экспортировать из модуля `pageIcons: Record<string,string>` — загрузчик подставит `pageIcons[icon]` |
| `element` | CE-тег страницы |

**Маршрут:** `#/p/<printerId>/<pageId>?<query>`. Страница получает query как
`params` (`?file=a.gcode` → `params.file`). Так делаются deep-link'и:
другой плагин (или пользователь) может послать на вашу страницу
`#/p/<printer>/<pageId>?file=…`.

**Показ.** Страницы всех зарегистрированных плагинов попадают в боковую панель.
Пользователь может скрыть страницу для конкретного принтера в
Settings → Pages. По умолчанию страница видна.

**Заголовок страницы** хост не рисует: название задаётся пунктом боковой
панели, внутри страницы используйте заголовки панелей.

**Компоновка.** Страница занимает всю область main и скроллится вместе с ней.
Рекомендуемая структура — вертикальный стек панелей. Допустим grid из
нескольких независимо скроллящихся панелей, если они образуют одну рабочую
поверхность (пример: консоль — лог + справочник команд).

**Идентификатор.** Страница ищется по `id` среди *всех* плагинов, видимость
хранится по голому `id`: два плагина с одинаковым `id` страницы конфликтуют.

## 2. Виджеты

```json
{
  "widgets": [
    {
      "type": "acme-gauge",
      "provider": "acme/hello",
      "titleKey": "hello.gauge",
      "element": "acme-gauge-widget",
      "headerElement": "acme-gauge-header",
      "defaultSize": { "w": 4, "h": 3 },
      "minSize": { "w": 2, "h": 2 }
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `type` | вид виджета (`temperature-graph`, `camera`, …) |
| `provider` | конкретная реализация; обычно `manifest.id` |
| `titleKey` | i18n-ключ заголовка; **заголовок рисует хост** в шапке карточки |
| `element` | CE тела виджета |
| `headerElement` | CE, который хост положит в шапку карточки справа от заголовка (кнопки, тумблеры); `params` = `{}` |
| `defaultSize` | размер при добавлении в клетках сетки; по умолчанию 4×3 |
| `minSize` | минимальный размер при ресайзе; по умолчанию 2×2 |

### type и provider

Виджет — это пара **`type` + `provider`**. Несколько плагинов могут предложить
разные провайдеры для одного `type`; пользователь выбирает провайдера в карточке
виджета (переключатель появляется только если провайдеров больше одного). Если
выбор не сделан — берётся первый зарегистрированный. Чтобы *заменить* встроенный
виджет, зарегистрируйте тот же `type` со своим `provider`.

Типы, из которых хост собирает дашборд по умолчанию:
`tools`, `temperature-graph`, `console`, `outputs`, `jobs-table`,
`gcode-preview`, `bed-mesh`, `camera`, `macros`.

### Сетка

12 колонок, высота строки — `--grid-row-height` (80px), на узких экранах сетка
схлопывается в одну колонку. Раскладка хранится на принтер
(`dashboardLayout`), редактируется в режиме `#/dashboard?edit=1`.

### Параметры

Тело виджета получает `params` = query-параметры маршрута дашборда (например,
`edit: '1'` в режиме редактирования, `preview: <файл>` при deep-link'е на превью).

### Дизайн виджета

Виджет — уменьшенная страница: тот же визуальный язык панели, выше плотность
контента, второстепенное скрыто, действия — в шапке (через `headerElement`) или
переносятся в меню / открывают полную страницу.

## 3. Баннеры

```json
{ "banners": [ { "id": "acme-warn", "element": "acme-warn-banner" } ] }
```

Баннер — блок в потоке сверху main. Баннеры всех плагинов стекаются по порядку
регистрации и **раздвигают** контент (не перекрывают).

- **Видимость решает плагин.** Хост всегда монтирует элемент; когда сообщать
  нечего, элемент должен отрисовывать *ничего* (пустой контент без высоты).
- `params = { mode, route }`:
  - `mode` — `'expanded'` или `'collapsed'`; хост сворачивает баннеры при
    прокрутке вниз (порог 32px) и разворачивает при прокрутке к началу;
  - `route` — `'dashboard'` | `'plugin-page'` | `'settings'`.
- Поле `scope` в типе объявлено, но хостом не применяется — фильтруйте по
  `params.route` сами.
- **Ручное управление.** Баннер может запросить развёрнутое или свёрнутое
  состояние баблящими событиями (достаточно, чтобы событие всплыло до main):

  ```js
  this.dispatchEvent(new CustomEvent('mpu:banner-expand',   { bubbles: true, composed: true }));
  this.dispatchEvent(new CustomEvent('mpu:banner-collapse', { bubbles: true, composed: true }));
  ```

  После `expand` хост удерживает развёрнутое состояние до прокрутки к началу;
  после `collapse` — до следующего `expand`.
- Баннер **не дублирует** offline-overlay: баннер — состояние Klipper/плагина,
  offline-overlay — соединение с Moonraker.

## 4. Оверлеи

```json
{ "overlays": [ { "id": "acme-dialog", "element": "acme-dialog-overlay" } ] }
```

Оверлей — плавающее окно (обычно модальное) поверх main и правой панели, под
offline-overlay. Типовой случай: диалог, который плагин открывает по состоянию
принтера (например, подтверждение ручного зондирования).

**Чем оверлей отличается от обычного всплывающего окна.** Всплывающее окно
(поповер, диалог внутри страницы или виджета) плагин может показать только на
своей странице, пока смонтирован его элемент. Оверлей — постоянная поверхность:
его элемент смонтирован всегда, поэтому плагин может показать окно **на любой
странице и в любом месте интерфейса** — например, диалог ручного зондирования
появится, даже если пользователь в этот момент на странице консоли. Если окно
должно быть доступно только внутри вашей страницы, оверлей не нужен.

Побочное следствие: так как оверлей смонтирован всегда, он подходит и для запуска
фоновой логики плагина, которой нужно жить независимо от страниц (например,
отслеживание состояния всех принтеров для гардов — см. [guards.md](guards.md)).
Горячие клавиши для действий оверлея объявляйте с `scope: 'global'`
(см. [hotkeys.md](hotkeys.md)).

Как это устроено:

- Хост монтирует **постоянный слой** `position: fixed; inset: 0` с
  `z-index: var(--z-plugin-overlays, 60)`. Сам слой и обёртка элемента имеют
  `pointer-events: none`, а **все потомки вашего элемента получают
  `pointer-events: auto`**.
- Элемент монтируется всегда (параметры `{}`), показывать/скрывать содержимое
  должен **сам плагин**. Когда окно закрыто, элемент не должен рендерить ничего
  (иначе его потомки перехватят клики по интерфейсу под слоем).
- Для модального окна сделайте внутри элемента свой `position: fixed` бэкдроп и
  диалог, с `z-index` в пределах вашего слоя.
- Оверлей — для всплывающих окон, а не для постоянного контента.

Типичный каркас:

```js
class AcmeDialog extends HTMLElement {
  #open = false;
  connectedCallback() {
    this.#off = this.api.moonraker().subscribe({ manual_probe: ['is_active'] }, (d) => {
      this.#open = d.manual_probe?.is_active === true;
      this.#render();
    });
  }
  #render() {
    this.innerHTML = this.#open
      ? `<div class="backdrop"><div class="dialog">…</div></div>`
      : '';                                 // закрыто → пусто
  }
}
```

## 5. Чипы быстрого доступа

Чип — миниатюрный glanceable-элемент полосы под баннерами: состояние + одно
действие. Полоса — «мозаика» чипов, расставленных пользователем.

```json
{
  "chips": [
    {
      "type": "gauge",
      "provider": "acme/hello",
      "titleKey": "hello.chip.gauge",
      "element": "acme-gauge-chip",
      "pickerElement": "acme-gauge-picker",
      "icon": "file"
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `type` | тип чипа внутри плагина (`temperature`, `macro`, …) |
| `provider` | обычно `manifest.id` |
| `titleKey` | заголовок секции в диалоге добавления |
| `element` | CE самого чипа |
| `pickerElement` | CE-каталог доступных предметов для диалога добавления |

### Модель

Хост хранит **только дескрипторы размещения** (`mpu:v2:settings:<printerId>`,
ключ `quickChips`): `{ instanceId, type, provider, id, label? }`.
`id` — ключ «предмета» внутри вашего плагина (имя датчика, макроса, устройства);
хост его не интерпретирует. Что за предметы бывают и как они выглядят —
дело плагина.

### Чип (`element`)

- `params = { chipId, chipLabel?, edit: '1' | '0' }`.
  `chipId` — тот самый `id` предмета; `chipLabel` — пользовательская метка.
- Корень чипа тянется на всю высоту слота (**80px**), ширина — по содержимому;
  ограничивайте её (`max-width` + `text-overflow: ellipsis`) на стороне плагина.
- Действие раскрывайте **поповером**, а не расширением чипа на месте
  (иначе полоса перестраивается).
- В `edit === '1'` (режим редактирования дашборда) хост рисует свои
  аффордансы (рамка, «+», крестики, перетаскивание). Чип в этом режиме не
  должен выполнять действий.
- Нет предмета (датчик исчез) → рисуйте состояние *missing*: пунктирная
  рамка и приглушённый текст.
- Действия чипа — обычный `api.moonraker().request()`, поэтому гарды их видят.

### Picker (`pickerElement`)

- `params = { edit: '1', placed: '<JSON-массив id>' }` — `placed` содержит `id`
  уже размещённых предметов **этого type и provider**; picker может скрыть или
  заглушить их.
- Picker перечисляет доступные предметы и по клику сообщает выбор баблящим
  событием:

  ```js
  el.dispatchEvent(new CustomEvent('mpu:chip-pick', {
    bubbles: true, composed: true,
    detail: { id: 'extruder', label: 'Hotend' },   // label необязателен
  }));
  ```

  `type` и `provider` хост берёт из обёртки секции, не из события. Событие
  потребляется диалогом добавления; это не шина плагинов.

### Прочее

- Плагин с отключённым/удалённым провайдером оставляет в полосе «призрачную»
  плашку *provider missing*; в режиме просмотра полоса из одних призраков скрыта.
- Чипы показываются только плагинов, применимых к активному принтеру
  (`printerIds` записи плагина).
- Состав чипов по умолчанию — решение хоста: `temperature` для `extruder` и
  `heater_bed` от `@core/widgets`, `livez` от `@core/calibrations`; сторонние
  плагины в него не входят.

## 6. Fleet-панели

Fleet-режим — полноэкранный drawer хоста со сеткой карточек всех принтеров.

```json
{ "printerPanels": [ { "id": "acme-state", "element": "acme-state-panel",
                       "titleKey": "hello.fleet.state" } ] }
```

- Элемент создаётся **по одному экземпляру на каждый настроенный принтер**.
  `params = { printerId }`. Объект `params` стабилен между перерисовками —
  иначе CE пересоздавался бы.
- Читайте данные **своего** принтера через `api.moonrakerFor(params.printerId)`,
  настройки — через `api.settingsFor(params.printerId)`.
- `api.moonraker()` и `api.settings` здесь **не подходят**: они про *активный*
  принтер, а fleet не меняет активного принтера.
- Панели складываются в стек внутри карточки в порядке регистрации. Пользователь
  может переупорядочить и скрыть панели («Редактировать панели» в шапке fleet);
  `titleKey` используется как название в этом редакторе.
- Рекомендуется делать панели **read-only**: действия по неактивным принтерам
  пока не рекомендуются (гарды плагинов, не знающих о целевом принтере, будут
  принимать решение по состоянию активного — см. [guards.md](guards.md#target-scoped-гарды)).
- Закрытие fleet = размонтирование: подписки и стримы освобождаются.
  Кэшируйте то, что дорого пересоздавать (на уровне модуля).
- Высота панели — по содержимому; хост рисует шапку карточки (имя принтера,
  статус соединения, «Активировать»).

## 7. Горячие клавиши

Подробности — в [hotkeys.md](hotkeys.md). Коротко:

```json
{ "hotkeys": [ { "id": "acme-refresh", "scope": "plugin",
                 "keys": "Alt+R", "handler": "refreshHandler",
                 "titleKey": "hello.hotkey.refresh" } ] }
```

Области: `global` (везде), `dashboard` (только дашборд), `plugin` (только на
странице плагина-владельца). Обработчик — экспорт модуля
`(api, event) => void | Promise<void>`.

## 8. Правая панель (для справки)

Уникальный слот. Хост принимает `rightPanel` **только** у `@core/system`; у любого
другого плагина вклад отклоняется с предупреждением в консоль. Remote-плагины
правую панель использовать не могут.
