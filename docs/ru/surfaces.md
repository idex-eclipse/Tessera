# Справочник по поверхностям (вкладам плагинов)

«Поверхность» — место в интерфейсе хоста, куда плагин может подмонтировать свой
Custom Element. Хост владеет самим местом (раскладка, z-порядок, показ/скрытие
контейнера), плагин владеет содержимым.

| Поверхность | Манифест | Где живёт | Кто решает, показывать ли | Remote |
|---|---|---|---|---|
| [Страница](#1-страницы) | `pages[]` | область main, пункт в боковой панели | пользователь (Settings → Pages) | да |
| [Виджет](#2-виджеты) | `widgets[]` | сетка дашборда | пользователь (раскладка дашборда) | да |
| [Баннер](#3-баннеры) | `banners[]` | сверху main, в потоке | **плагин** | да |
| [Свёрнутый баннер](#свёрнутый-вид) | `collapsedBanners[]` | строка свёрнутого баннера | **плагин** | да |
| [Оверлей](#4-оверлеи) | `overlays[]` | поверх main и правой панели | **плагин** | да |
| [Чип](#5-чипы-быстрого-доступа) | `chips[]` | полоса под баннерами | пользователь (edit-режим) | да |
| [Fleet-панель](#6-fleet-панели) | `printerPanels[]` | карточка принтера в fleet | пользователь (редактор панелей) | да |
| [Hotkey](#7-горячие-клавиши) | `hotkeys[]` | глобально | пользователь (Settings → Hotkeys) | да |
| Правая панель | `rightPanel` | колонка справа | — | **нет** (только `@core/system`) |
| [Дополнение](#10-точки-расширения) | `extensions[]` | точка другого плагина | ставит владелец; решают режим и пользователь | да |

Слои сверху вниз:

```
окно авторизации      — 900, запрос входа (только хост)
тосты                 — 550, центр уведомлений (только хост)
центр уведомлений     — 450, список рядом с правой панелью (только хост)
диалоги хоста         — 300, подтверждения и диалоги настроек
меню вкладок принтеров — 250
fleet-режим           — 200, полноэкранная панель
offline-overlay       — 100, статус соединения (только хост; скрыт на Настройках)
оверлеи плагинов      — 60, модальные окна
боковые панели, узко  — 40, меню и правая панель поверх содержимого
правая панель         — 30, колонка справа
панель правки, узко   — 10, закреплена при прокрутке страницы
баннеры               — в потоке сверху main (раздвигают контент)
полоса чипов          — в потоке под баннерами
main-контент          — дашборд / страница плагина / Settings
```

## Общие правила для всех поверхностей

1. **Один вклад — один Custom Element.** Поле `element` — тег, который плагин
   зарегистрировал в своём модуле.
2. **Хост передаёт `api` и `params`** свойствами (см. [plugin-development.md](plugin-development.md#4-контракт-custom-element)).
3. **Бизнес-данные хост не читает.** Всё, что поверхность показывает, она берёт
   из Moonraker сама. Единственное исключение — непрозрачный fleet-индекс (теги и
   текст для поиска, которые публикуют fleet-панели; хост их не интерпретирует —
   см. [architecture.md](architecture.md#fleet-индекс)).
4. **Единый визуальный язык** — панель (см. [i18n-and-theming.md](i18n-and-theming.md#панельный-язык)).
5. Хост монтирует элемент, когда поверхность появляется на экране, и размонтирует,
   когда исчезает. Освобождайте подписки в `disconnectedCallback`. **При смене объекта
   `params` хост заменяет элемент новым**, поэтому состояние внутри него теряется:
   у баннера при смене `mode`, `route` или `narrow`, у чипа при смене `edit` или
   `narrow`, у тела виджета при смене query маршрута или `narrow`. То, что должно
   сохраниться, держите в настройках или на уровне модуля.
6. Для страниц и виджетов `id`/`type` считаются глобальными именами — используйте
   префикс плагина.

## 1. Страницы

```json
{
  "pages": [
    { "id": "acme-hello", "titleKey": "hello.title", "icon": "file",
      "element": "acme-hello-page" }
  ]
}
```

| Поле | Описание |
|---|---|
| `id` | идентификатор страницы; **глобально уникален** (см. ниже) |
| `titleKey` | i18n-ключ названия в боковой панели |
| `icon` | имя встроенной иконки хоста (по умолчанию «файл») |
| `iconSvg` | своя иконка: строка SVG. Можно не писать в манифесте, а экспортировать из модуля `pageIcons: Record<string,string>` — загрузчик подставит `pageIcons[icon]` |
| `element` | CE-тег страницы |

**Маршрут:** `#/p/<printerId>/<pageId>?<query>`. Страница получает query как
`params` (`?file=a.gcode` → `params.file`). Так делаются deep-link'и:
другой плагин (или пользователь) может послать на вашу страницу
`#/p/<printer>/<pageId>?file=…`.

**Показ.** Страницы всех зарегистрированных плагинов попадают в боковую панель.
Пользователь может скрыть страницу для конкретного принтера в
Settings → Pages. По умолчанию страница видна.

**Заголовок страницы** хост не рисует: название задаётся пунктом боковой
панели, внутри страницы используйте заголовки панелей.

**Компоновка.** Страница занимает main ниже баннеров и чипов и прокручивается там; на
узком экране прокручивается вся main вместе с баннерами и чипами.
Рекомендуемая структура — вертикальный стек панелей. Допустим grid из
нескольких независимо скроллящихся панелей, если они образуют одну рабочую
поверхность (пример: консоль — лог + справочник команд).

**Идентификатор.** Страница ищется по `id` среди *всех* плагинов, видимость
хранится по голому `id`: два плагина с одинаковым `id` страницы конфликтуют.

## 2. Виджеты

```json
{
  "widgets": [
    {
      "type": "acme-gauge",
      "provider": "acme/hello",
      "titleKey": "hello.gauge",
      "element": "acme-gauge-widget",
      "headerElement": "acme-gauge-header",
      "defaultSize": { "w": 4, "h": 3 },
      "minSize": { "w": 2, "h": 2 }
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `type` | вид виджета (`temperature-graph`, `camera`, …) |
| `provider` | конкретная реализация; обычно `manifest.id` |
| `titleKey` | i18n-ключ заголовка; **заголовок рисует хост** в шапке карточки |
| `element` | CE тела виджета |
| `headerElement` | CE, который хост положит в шапку карточки справа от заголовка (кнопки, тумблеры), а если не помещается, то на вторую строку; `params` = `{}` |
| `defaultSize` | размер при добавлении в клетках сетки; по умолчанию 4×3 |
| `minSize` | минимальный размер при ресайзе; по умолчанию 2×2 |

### type и provider

Виджет — это пара **`type` + `provider`**. Несколько плагинов могут предложить
разные провайдеры для одного `type`; пользователь выбирает провайдера в карточке
виджета (переключатель появляется только если провайдеров больше одного). Если
выбор не сделан — берётся первый зарегистрированный. Чтобы *заменить* встроенный
виджет, зарегистрируйте тот же `type` со своим `provider`.

Выбор действует только на дашборд по умолчанию. В настроенной раскладке у каждого
размещённого виджета записан свой `provider`, поэтому там переключатель ничего не меняет:
удалите виджет и добавьте его снова с другим провайдером.

Типы, из которых хост собирает дашборд по умолчанию:
`tools`, `temperature-graph`, `console`, `outputs`, `jobs-table`,
`gcode-preview`, `bed-mesh`, `camera`, `macros`.

### Сетка

12 колонок, высота строки — `--grid-row-height` (80px); когда сам dashboard уже
768px (считается ширина области, а не окна: сайдбар и правая панель в счёт),
сетка становится одной колонкой, а виджет по-прежнему занимает `h` рядов, поэтому
высота у него всегда определена. Раскладка хранится на принтер
(`dashboardLayout`), редактируется в режиме `#/dashboard?edit=1`.

### Параметры

Тело виджета получает `params` = query-параметры маршрута дашборда (например,
`preview: <файл>` при deep-link'е на превью) и `narrow` (см.
[Узкие экраны](#9-узкие-экраны)). В режиме редактирования хост показывает вместо виджетов
карточки-заглушки, поэтому тело и `headerElement` не смонтированы.

### Дизайн виджета

Виджет — уменьшенная страница: тот же визуальный язык панели, выше плотность
контента, второстепенное скрыто, действия — в шапке (через `headerElement`) или
переносятся в меню / открывают полную страницу.

## 3. Баннеры

```json
{ "banners": [ { "id": "acme-warn", "element": "acme-warn-banner" } ] }
```

Баннер — блок в потоке сверху main. Баннеры всех плагинов стекаются по порядку
регистрации и **раздвигают** контент (не перекрывают).

- **Видимость решает плагин.** Хост всегда монтирует элемент; когда сообщать
  нечего, элемент должен отрисовывать *ничего* (пустой контент без высоты).
- `params = { mode, route, narrow }`:
  - `mode` — `'expanded'` или `'collapsed'`: `'collapsed'`, пока вместо этого баннера хост
    показывает [свёрнутый вид](#свёрнутый-вид). На широком экране ещё и при прокрутке вниз
    (порог 32px, у начала снова `'expanded'`), хотя баннер при этом остаётся на экране;
  - `route` — `'dashboard'` | `'plugin-page'` | `'settings'`;
  - `narrow` — `'true'` | `'false'`, см. [Узкие экраны](#9-узкие-экраны).
- Поле `scope` в типе объявлено, но хостом не применяется — фильтруйте по
  `params.route` сами.
- **Ручное управление.** Баннер может запросить развёрнутое или свёрнутое
  состояние баблящими событиями:

  ```js
  this.dispatchEvent(new CustomEvent('mpu:banner-expand',   { bubbles: true, composed: true }));
  this.dispatchEvent(new CustomEvent('mpu:banner-collapse', { bubbles: true, composed: true }));
  ```

  `expand` показывает этот баннер полностью, даже если хост свернул бы его, как нажатие на
  его свёрнутую строку; `collapse` возвращает его к решению хоста. На другие баннеры это не
  влияет. На широком экране они также удерживают `mode`, общий для всех баннеров: после
  `expand` до прокрутки к началу, после `collapse` до следующего `expand`.
- Баннер **не дублирует** offline-overlay: баннер — состояние Klipper/плагина,
  offline-overlay — соединение с Moonraker.

### Когда хост сворачивает баннеры

Хост старается оставить баннеры на виду и убирает их по шагам, считая от высоты main.
Каждый шаг применяется, только если предыдущего не хватило:

| Шаг | Условие | Результат |
|---|---|---|
| 1 | баннер выше 35% | этот баннер свёрнут |
| 2 | баннеры вместе занимают больше 40% | свёрнуты **все**, чтобы не было расхождения по стилю |
| 3 | свёрнутые строки занимают больше 25% (от двух баннеров) | все под закрытым аккордеоном «Баннеры (N)» |

На узком экране баннеры всегда свёрнуты по умолчанию, а два и более всегда под аккордеоном
(см. [Узкие экраны](#9-узкие-экраны)).

Нажатие на свёрнутую строку раскрывает только этот баннер, тонкая кнопка вплотную к его нижнему
краю сворачивает его обратно. Для этого хост убирает у корня элемента нижний отступ и нижние
скругления, поэтому рамку баннера держите на корне. Смена состояний анимируется, поэтому баннер не должен рассчитывать, что его высота
окончательна в момент показа.

### Свёрнутый вид

```json
{
  "banners": [ { "id": "acme-warn", "element": "acme-warn-banner" } ],
  "collapsedBanners": [
    { "id": "acme-warn-collapsed", "banner": "acme-warn", "element": "acme-warn-banner-collapsed" }
  ]
}
```

Пока баннер свёрнут, вместо него хост показывает строку с его свёрнутым видом. `banner` —
`id` баннера того же плагина; вклад со ссылкой на неизвестный баннер отбрасывается с
предупреждением.

- `params = { route, narrow }`. Как и баннер, элемент смонтирован всегда.
- Он показывается, только пока у его баннера ненулевая высота; когда сообщать нечего,
  отрисовывайте *ничего*.
- Он **только показывает информацию**: одна строка, без своего оформления (его даёт
  строка хоста). Клик всплывает до хоста и раскрывает баннер; если свой контрол
  действительно нужен, вызовите `stopPropagation()`.
- Для баннера без свёрнутого вида показывается строка с именем плагина.

## 4. Оверлеи

```json
{ "overlays": [ { "id": "acme-dialog", "element": "acme-dialog-overlay" } ] }
```

Оверлей — плавающее окно (обычно модальное) поверх main и правой панели, под
fleet-режимом, offline-overlay и диалогами хоста. Типовой случай: диалог, который плагин открывает по состоянию
принтера (например, подтверждение ручного зондирования).

**Чем оверлей отличается от обычного всплывающего окна.** Всплывающее окно
(поповер, диалог внутри страницы или виджета) плагин может показать только на
своей странице, пока смонтирован его элемент. Оверлей — постоянная поверхность:
его элемент смонтирован всегда, поэтому плагин может показать окно **на любой
странице** (если его не закрывает слой выше) — например, диалог ручного зондирования
появится, даже если пользователь в этот момент на странице консоли. Если окно
должно быть доступно только внутри вашей страницы, оверлей не нужен.

Побочное следствие: так как оверлей смонтирован всегда, он подходит и для запуска
фоновой логики плагина, которой нужно жить независимо от страниц (например,
отслеживание состояния всех принтеров для гардов — см. [guards.md](guards.md)).
Горячие клавиши для действий оверлея объявляйте с `scope: 'global'`
(см. [hotkeys.md](hotkeys.md)).

Как это устроено:

- Хост монтирует **постоянный слой** `position: fixed; inset: 0` с
  `z-index: var(--z-plugin-overlays, 60)`. Сам слой и его обёртка имеют
  `pointer-events: none`, а **всё внутри обёртки, ваш элемент и его потомки, получает
  `pointer-events: auto`**.
- Элемент монтируется всегда (параметры `{}`), показывать/скрывать содержимое
  должен **сам плагин**. Когда окно закрыто, элемент не должен рендерить ничего
  (иначе его потомки перехватят клики по интерфейсу под слоем).
- Для модального окна сделайте внутри элемента свой `position: fixed` бэкдроп и
  диалог, с `z-index` в пределах вашего слоя.
- Оверлей — для всплывающих окон, а не для постоянного контента.

Типичный каркас:

```js
class AcmeDialog extends HTMLElement {
  #open = false;
  connectedCallback() {
    this.#off = this.api.moonraker().subscribe({ manual_probe: ['is_active'] }, (d) => {
      this.#open = d.manual_probe?.is_active === true;
      this.#render();
    });
  }
  #render() {
    this.innerHTML = this.#open
      ? `<div class="backdrop"><div class="dialog">…</div></div>`
      : '';                                 // закрыто → пусто
  }
}
```

## 5. Чипы быстрого доступа

Чип — миниатюрный glanceable-элемент полосы под баннерами: состояние + одно
действие. Полоса — «мозаика» чипов, расставленных пользователем.

```json
{
  "chips": [
    {
      "type": "gauge",
      "provider": "acme/hello",
      "titleKey": "hello.chip.gauge",
      "element": "acme-gauge-chip",
      "pickerElement": "acme-gauge-picker"
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `type` | тип чипа внутри плагина (`temperature`, `macro`, …) |
| `provider` | обычно `manifest.id` |
| `titleKey` | заголовок секции в диалоге добавления |
| `element` | CE самого чипа |
| `pickerElement` | CE-каталог доступных предметов для диалога добавления |

### Модель

Хост хранит **только дескрипторы размещения** (`mpu:v2:settings:<printerId>`,
ключ `quickChips`): `{ instanceId, type, provider, id, label? }`.
`id` — ключ «предмета» внутри вашего плагина (имя датчика, макроса, устройства);
хост его не интерпретирует. Что за предметы бывают и как они выглядят —
дело плагина.

### Чип (`element`)

- `params = { chipId, chipLabel?, edit: '1' | '0', narrow: 'true' | 'false' }`.
  `chipId` — тот самый `id` предмета; `chipLabel` — пользовательская метка.
- Корень чипа тянется на всю высоту слота (**80px**), ширина — по содержимому;
  ограничивайте её (`max-width` + `text-overflow: ellipsis`) на стороне плагина.
- Если на широком экране чипы занимают больше 25% высоты main, хост сворачивает их в
  закрытый аккордеон «Быстрый доступ» (в edit-режиме — никогда). В отличие от узкого экрана,
  скролл его не закрывает.
- Действие раскрывайте **поповером**, а не расширением чипа на месте
  (иначе полоса перестраивается). По умолчанию открывайте его **вниз** (полоса стоит под
  баннерами и шапкой): сторону и выравнивание (LTR/RTL) решают `shouldOpenAbove()` и
  `shouldAlignToEnd()` из `plugins/shared/popover-align.ts`. Полоса может прокручиваться
  при любой ширине экрана, поэтому поповер всегда должен использовать `position: fixed`
  и выходить из её обрезающей области. `placeChipPopover()` из того же файла принимает
  прямоугольник чипа и примерный размер поповера и возвращает строку CSS-стиля для него.
- В `edit === '1'` (режим редактирования дашборда) хост рисует свои
  аффордансы (рамка, «+», крестики, кнопки порядка, перетаскивание). Чип в этом режиме
  не должен выполнять действий.
- Нет предмета (датчик исчез) → рисуйте состояние *missing*: пунктирная
  рамка и приглушённый текст.
- Действия чипа — обычный `api.moonraker().request()`, поэтому гарды их видят.

### Picker (`pickerElement`)

- `params = { edit: '1', placed: '<JSON-массив id>' }` — `placed` содержит `id`
  уже размещённых предметов **этого type и provider**; picker может скрыть или
  заглушить их.
- Picker перечисляет доступные предметы и по клику сообщает выбор баблящим
  событием:

  ```js
  el.dispatchEvent(new CustomEvent('mpu:chip-pick', {
    bubbles: true, composed: true,
    detail: { id: 'extruder', label: 'Hotend' },   // label необязателен
  }));
  ```

  `type` и `provider` хост берёт из обёртки секции, не из события. Событие
  потребляется диалогом добавления; это не шина плагинов.

### Прочее

- Плагин с отключённым/удалённым провайдером оставляет в полосе «призрачную»
  плашку *provider missing*; в режиме просмотра полоса из одних призраков скрыта.
- Чипы показываются только плагинов, применимых к активному принтеру
  (`printerIds` записи плагина).
- Состав чипов по умолчанию — решение хоста: `temperature` для `extruder` и
  `heater_bed` от `@core/widgets`, `livez` от `@core/calibrations`; сторонние
  плагины в него не входят.

## 6. Fleet-панели

Fleet-режим — полноэкранный drawer хоста со сеткой карточек всех принтеров.

```json
{ "printerPanels": [ { "id": "acme-state", "element": "acme-state-panel",
                       "titleKey": "hello.fleet.state" } ] }
```

- Элемент создаётся **по одному экземпляру на каждый настроенный принтер**.
  `params = { printerId }`. Объект `params` стабилен между перерисовками —
  иначе CE пересоздавался бы.
- Читайте данные **своего** принтера через `api.moonrakerFor(params.printerId)`,
  настройки — через `api.settingsFor(params.printerId)`.
- `api.moonraker()` и `api.settings` здесь **не подходят**: они про *активный*
  принтер, а fleet не меняет активного принтера.
- Панели складываются в стек внутри карточки в порядке регистрации. Пользователь
  может переупорядочить и скрыть панели («Редактировать панели» в шапке fleet);
  `titleKey` используется как название в этом редакторе.
- Рекомендуется делать панели **read-only**: действия по неактивным принтерам
  пока не рекомендуются (гарды плагинов, не знающих о целевом принтере, будут
  принимать решение по состоянию активного — см. [guards.md](guards.md#target-scoped-гарды)).
- Чтобы участвовать в **поиске и фильтрах** fleet, публикуйте индекс из панели:
  `api.fleet.publish(params.printerId, { tags, searchText })` (в `$effect` или
  `connectedCallback`) и вызывайте `api.fleet.retract(params.printerId)`, когда
  панель убирается. См. [plugin-api.md](plugin-api.md#fleet).
- Закрытие fleet = размонтирование: подписки и стримы освобождаются.
  Кэшируйте то, что дорого пересоздавать (на уровне модуля).
- Высота панели — по содержимому; хост рисует шапку карточки (имя принтера,
  статус соединения, «Активировать»).

## 9. Узкие экраны

Брейкпоинт — **768px** (`NARROW_BREAKPOINT` в `ui-store`), он измеряется в двух местах:

- Боковые панели следуют ширине *окна*: узко при ширине ≤ 768px (`ui.isNarrow`).
- Баннеры, чипы и виджеты следуют ширине *рабочей области*: узко, когда её содержимое уже
  768px (`core/narrow-width.ts`). Отступы main и открытые сайдбары идут в счёт, поэтому на
  широком окне для них тоже может быть «узко».

Узкий режим — это *маленькая область*, а не сенсорное устройство: мышь, клавиатура и
горячие клавиши работают так же, как на десктопе.

### `params.narrow`

Баннеры, свёрнутые виды, чипы, тела виджетов и правая панель получают
`params.narrow` = `'true'` | `'false'` — строкой, как и остальные `params`. Страницы,
оверлеи, fleet-панели, `headerElement` и picker его не получают. При смене значения хост
заменяет элемент (см. [общие правила](#общие-правила-для-всех-поверхностей)), поэтому новый
элемент всегда стартует с актуальным значением и следить за `narrow` на лету не нужно. Это
лишь удобный флаг: что помещается внутри вашей поверхности, зависит от её размера, и для
этого нужны container queries (см. ниже).

### Что хост делает сам

- **Боковые панели** (меню и правая панель) открываются поверх содержимого на всю
  ширину под шапкой; открыта не более одной. Правая панель при этом всегда
  получает `collapsed: 'false'`, сохранённое «свёрнуто» и ширина игнорируются.
- **Монтирование.** Боковая панель монтируется только пока открыта. Всё, что должно
  работать при закрытой панели (фоновые источники, обработчики хоткеев), обязано
  жить в постоянно смонтированной поверхности (оверлее) и не зависеть от DOM панели.
  Центр уведомлений и его тосты таким кодом не являются: они принадлежат хосту и
  смонтированы всегда (см. [`api.notifications`](plugin-api.md#notifications)).
  Клавиши `R` и `L` переключают правую панель и левое меню: на широком экране —
  сворачивают/разворачивают, на узком — открывают/закрывают оверлей.
- **Баннеры** по умолчанию [свёрнуты](#свёрнутый-вид), даже единственный; два и более всегда
  под закрытым аккордеоном «Баннеры (N)». Видимым считается баннер с ненулевой высотой, поэтому
  по-прежнему отрисовывайте *ничего*, когда сообщать нечего.
- **Чипы** собраны в аккордеон «Быстрый доступ» (свёрнут по умолчанию, в
  edit-режиме открыт). В открытом виде это лента в две строки с горизонтальной
  прокруткой. Высота чипа не меняется (80px).
- **Сворачивание при прокрутке.** Прокрутка вниз (порог 32px) сворачивает и баннеры, и
  чипы; раскрывает их только нажатие, а прокрутка к началу — нет. Учитывается и прокрутка
  внутренних контейнеров уровня страницы, но не мелких списков внутри виджетов и не
  прокрутка без действий пользователя (например, лог консоли, следующий за новыми строками).

### Адаптация внутри плагина

Используйте container queries, а не `@media`: страница или виджет бывают узкими и на широком
экране. Сделайте корень поверхности контейнером
(`:global(mpu-x) { display:block; container-type:inline-size }`) и запрашивайте его:
`@container (max-width: 720px)` — раскладка в столбец, `480px` — компакт. Диалог с
`position: fixed` не лежит ни в каком контейнере: контейнером должна быть его панель.
Таблицы, которые не должны скроллиться вбок: `plugins/shared/responsive/card-table.css`
превращает `table.card-table` (с `data-label` у каждой `td`) в карточки уже при ширине до
520px. Размеры зон нажатия задавайте через `@media (pointer: coarse)`, а не по ширине окна.
У core-плагинов есть готовые помощники, см.
[plugin-development.md](plugin-development.md#общие-помощники).

### Редактирование дашборда

Режим редактирования открывается из Settings → «Редактировать раскладку»
(`#/dashboard?edit=1`). Панель кнопок стоит над полосой чипов: на широком экране вне
прокручиваемой области, на узком закреплена. Правки записываются сразу, поэтому
**«Сохранить»** только выходит из режима, а **«Отменить изменения»** возвращает раскладку
виджетов и быстрые чипы к состоянию на входе. Отмена и повтор действуют на обе части (см.
[hotkeys.md](hotkeys.md)).

- На широком дашборде карточка перетаскивается и меняет размер за края. На сенсорном экране
  перенос начинается долгим нажатием (400 мс), поэтому свайп по-прежнему прокручивает
  страницу.
- На узком дашборде карточки не перетаскиваются. Рядом с каждой карточкой линейка и кнопки
  «выше/ниже», справа от карточки, в RTL слева. Ползунок линейки меняет высоту по рядам, от
  `minSize.h` виджета до 16 рядов.
- Раскладка у обоих режимов одна, поэтому первое нажатие «выше/ниже» складывает её в одну
  колонку и перезаписывает широкую расстановку. Вернуть её можно отменой.
- В режиме редактирования у каждого чипа есть кнопки порядка на любом устройстве, и
  перетаскивание тоже работает.
- На широком дашборде редактор также выбирает раскладку полосы отдельно для каждого
  принтера: **«Построчно»** (по умолчанию, двухстрочная сетка) или **«Одна строка»**.
  Обе раскладки прокручиваются горизонтально при переполнении и сохраняют обычный
  фиксированный промежуток между чипами. Двухстрочная сетка использует тот же порядок по
  колонкам, что и мобильная раскладка, а оба чипа колонки получают ширину более широкого.
  Обычное вертикальное вращение колеса прокручивает обе ленты горизонтально без Shift;
  на краях ленты жест снова прокручивает страницу. На узком дашборде всегда используется
  двухстрочная сетка.

### Страница настроек

В мобильном режиме (окно ≤ 768px) или когда сама страница уже 560px, она показывает список
вкладок, а выбранная вкладка заменяет его и получает кнопку «Назад» (`#/settings` — список,
`#/settings/<id>` — вкладка). Иначе список стоит рядом с вкладкой, а `#/settings` открывает
General.

## 10. Точки расширения

Плагин можно **дополнять другими плагинами**. Владелец объявляет *точки расширения* —
что, какого вида и в каком режиме можно в него встроить, — и ставит их где хочет на своих
страницах, виджетах или баннерах. Плагин-дополнение объявляет *вклады* в точки других
плагинов (или в свои). Хост ведёт реестр, проверяет версии, разрешает конфликты и
монтирует вклад **с api самого дополнения**. Напрямую плагины по-прежнему не общаются.

```json
{
  "extensionPoints": [
    { "id": "tabs",   "kind": "tab", "mode": "append",      "version": 1, "titleKey": "acme.ext.tabs" },
    { "id": "shaper", "kind": "tab", "mode": "alternative", "version": 1, "titleKey": "acme.ext.shaper" }
  ]
}
```

```json
{
  "extensions": [
    { "point": "@core/calibrations#shaper", "kind": "tab", "version": 1,
      "id": "shaketune", "titleKey": "st.title", "element": "st-shaper",
      "available": "hasShakeTune" }
  ]
}
```

| Поле точки | Описание |
|---|---|
| `id` | уникален внутри плагина, без `#` и `/`; адрес — `<ownerPluginId>#<id>` |
| `kind` | `tab` \| `panel` \| `element` \| `action` — контракт вклада |
| `mode` | `append` (по умолчанию) \| `alternative` \| `replacement`; `action` — только append |
| `version` | целое > 0, мажор контракта params/context |
| `max` | только append: сколько вкладов показывает точка (по умолчанию без ограничения) |
| `default` | только alternative: `extension` (по умолчанию — первый доступный вклад) или `original` |
| `titleKey` | название точки в диалогах хоста и Settings → Plugins |

| Поле вклада | Описание |
|---|---|
| `point` | `<ownerPluginId>#<pointId>` |
| `kind`, `version` | должны совпадать с точкой, иначе вклад отбрасывается |
| `id`, `titleKey` | уникален внутри плагина (без `/`); название — на вкладке, панели, в меню |
| `element` | CE-тег для `tab`, `panel`, `element` |
| `headerElement` | только `panel`: CE в шапке панели |
| `handler` | только `action`: экспорт модуля `(api, context) => void \| Promise<void>` |
| `icon` | `action`: иконка пункта меню |
| `available` | экспорт модуля `(api, params) => boolean \| Promise<boolean>`; нет — доступен всегда |
| `order` | порядок среди вкладов точки (меньше — раньше, по умолчанию 0) |

### Виды

| kind | Рисует владелец | Даёт дополнение |
|---|---|---|
| `tab` | кнопку вкладки и место для тела | `element` — всё содержимое вкладки |
| `panel` | место; оболочку панели (заголовок + `headerElement` + тело) рисует хост | `element`, опц. `headerElement` |
| `element` | место в потоке, без хрома | `element`; когда показывать нечего, рендерит *пустоту* |
| `action` | кнопку или пункт меню по `api.extensions.list()` | `handler(api, context)`; схема context описана вместе с точкой |

### Режимы

| mode | Вкладов | Оригинал владельца | Выбор |
|---|---|---|---|
| `append` | до `max` | остаётся | — |
| `alternative` | сколько угодно | один из вариантов | пользователь: ПКМ → popover хоста |
| `replacement` | ровно один | не рендерится | нет |

- **alternative**: ПКМ, долгое нажатие на touch (500 мс) или клавиша ContextMenu на точке
  открывают popover хоста с «Оригиналом» и всеми доступными вкладами. Выбор хранится
  per-printer (как выбор провайдера виджета) и продублирован в Settings → Plugins. Хост
  реагирует, только если внутренний контент не вызвал `preventDefault()` на `contextmenu`.
- **replacement**: вешайте такие точки на крупные элементы своих поверхностей (секции тел
  виджетов, панели страниц, тело баннера). Недоступен вклад — показывается оригинал.
  Аварийные и печатные органы (E-stop, старт/пауза/отмена) заменяемыми не делайте.

### Доступность, версии, сон

- `available` вызывается с api дополнения при отрисовке точки и повторно на
  `notify_klippy_ready`, `notify_config_changed` и переподключении. Хост данные не читает.
- Несовпадение версии или вида отбрасывает вклад (предупреждение в консоли и в Settings → Plugins).
- Вклад в точку незагруженного или выключенного владельца *спит*, это не ошибка: он
  подключится, как только владелец появится.
- Набор точек — часть **версии владельца**, а не
  [plugin API](plugin-development.md#версия-plugin-api): новая точка или версия точки
  поднимает `version` владельца (в том числе встроенного плагина). Дополнение указывает
  нужную версию владельца в [`dependencies`](plugin-development.md#зависимости)
  (`{ "@core/calibrations": "3.0.0" }`, минимум). Если загруженный владелец старше, все
  вклады этого дополнения во владельца отбрасываются, а Settings → Plugins подсказывает,
  что обновить (Tessera для `@core/*`, иначе владельца); `tessera-ext` на такую Tessera
  дополнение не ставит, а владельца из реестра обновляет.
- Если владелец загружен и подходит под `dependencies` (или записи нет), но такой точки
  у него нет, вклад отбрасывается так же: владелец старше, чем нужно вкладу.

### Конфликты

Конфликт — применимых вкладов больше ёмкости точки (`replacement`: 1, `append`: `max`).
Детект статический (загружен + включён + применим к принтеру, `available` не учитывается).
Хост показывает диалог: выбрать победителей или оставить оригинал. **Пока конфликт не
разрешён, все конфликтующие вклады точки выключены.** «Позже» откладывает диалог до конца
сессии; в Settings → Plugins остаётся кнопка «Разрешить». Решение хранится на устройстве и
запрашивается заново, если изменился набор кандидатов.

### API владельца

```ts
api.extensions.list(pointId, params?)        // активные вклады (ExtensionRef[])
api.extensions.resolve(pointId, params?)     // { mode, original, active, options, conflict }
api.extensions.onChange(cb)                  // → unsubscribe
api.extensions.mount(container, ref, params?)// → { update(params), destroy() }
api.extensions.invoke(ref, context?)         // action
api.extensions.choice(pointId) / setChoice(pointId, ref | null)
api.extensions.openChooser(pointId, anchorEl | { x, y }, params?)
```

Оригинал рендерите, только когда `resolve(pointId).original` истинно. Владельцам на Svelte
SDK даёт обёртку, которая делает всё это сама:

```svelte
<script>
  import { ExtensionPoint } from '@sdk/svelte';
</script>

<ExtensionPoint point="shaper">
  {#snippet original()}<ShaperContent />{/snippet}
</ExtensionPoint>
<ExtensionPoint point="tabs" only={activeTabRef} />
```

### Прочие правила

- Хоткеи дополнения со `scope: 'plugin'` работают и там, где смонтирован его вклад; при
  совпадении комбинации побеждают хоткеи владельца страницы.
- Гарды не наследуются: дополнение объявляет гарды для своих команд.
- Deep link на вкладку дополнения: `?section=<extPluginId>/<id>`, разбирает владелец.
- Зависимости: владельцы точек, в которые встраивается дополнение, — его зависимости,
  с минимальными версиями из `dependencies`. `tessera-ext install` ставит или обновляет
  их из реестра (`requires` и `dependencies` в `registry.json`); `remove` не удаляет
  плагин, от которого зависят другие, без `--force`. `@core/*` приходят с Tessera: их
  версии — в `host/dist/core-plugins.json` сборки.
- Всплывающие окна, меню и лайтбоксы вклада должны жить в **top layer** браузера
  (`<dialog>.showModal()` или Popover API: `popover="auto"` + `popovertarget`). Вклад
  монтируется внутри страницы владельца: у его панелей часто `overflow: hidden`, а сама
  страница может быть size-контейнером (`container-type`) — это обрезает меню в потоке и
  превращает `position: fixed` в «фиксировано относительно контейнера». Образец —
  плагин Shake&Tune (Lit, `tessera-ext`): справка — `[popover]` с позиционированием из JS,
  лайтбокс графиков — `<dialog>`.

`@core/config` (все `version: 1`; вклад получает только свой api), начиная с версии
владельца `4.0.0`:

Встроенный редактор Config перед каждым сохранением `.cfg` или `.conf` в корне
Moonraker `config` копирует файл в `config/.backup/<относительный путь>.bak`,
создавая нужные вложенные папки. Если копирование не удалось, запись отменяется;
следующее сохранение заменяет копию. Копия остаётся и после команды перезапуска.
Кнопка «Сравнить» в редакторе показывает копию рядом с редактируемым текущим
файлом на широком экране и помечает изменённые строки на узком. Правки сохраняются
в редакторе после выхода из сравнения; во время сравнения доступно сохранение.
Слева показаны только реальные строки копии, без пустых строк diff. Кнопка
«Вернуть всю копию в редактор» заменяет текущий буфер; отдельные блоки можно
перенести кнопками между колонками или рядом с изменённой строкой на узком экране.
Эти действия не записывают файлы до сохранения; при следующем сохранении `.bak`
заменяется состоянием файла непосредственно перед записью.
Старые копии рядом с исходным файлом тоже можно сравнить. Сравнение доступно
и через меню файла. «Сохранить и перезапустить» после записи отправляет команду,
не ожидая ответа на перезапуск и не проверяя запуск службы. При ошибке запуска
Klipper (`error`) перезапускается его сервис через Moonraker; при состоянии
`shutdown` и в обычном состоянии отправляется перезапуск прошивки. После сохранения
`moonraker.conf` перезапускается Moonraker. Ошибки команды показываются в таблице
файлов; отсутствие ответа не удерживает редактор. Для возврата
к сохранённой версии файл из `.backup` также доступен для ручного возврата.
Расширение, заменяющее встроенный редактор, самостоятельно отвечает за запись
файлов и этот механизм не наследует.

| Точка | kind | mode | Где |
|---|---|---|---|
| `page` | element | replacement | всё содержимое страницы «Файлы конфигурации» (обе таблицы и нижние панели) |
| `table-config`, `table-other` | element | replacement | таблица файлов конфигурации / таблица логов, документов и примеров (последняя вместе с полосой вкладок) |

| `file-editor` | element | replacement | диалог текстового редактора (общая файловая таблица) |

#### Точка общего слайдера

`SliderField` (`plugins/shared/slider-field`) входит в каждый плагин, который его встраивает,
и общается с хостом от имени этого плагина, поэтому его точка объявляется в манифесте каждого
такого плагина (`sliderPoints('<i18nPrefix>')` из `plugins/shared/slider-field/extension-points.ts`).
Сейчас её объявляет только `@core/widgets`: она покрывает Tools, Outputs, Limits и LEDs, а также
чипы Outputs и Tuning. Слайдер слоёв в G-code preview — отдельный компонент, он не затронут.

- `slider` заменяет только **внешний вид** одного слайдера (подпись, поле ввода, кнопку сброса,
  ползунок). Ограничение min/max, защита от устаревшего значения и команды остаются в плагине.
- Params (строки): `label`, `value`, `min`, `max`, `step`, `unit`, `decimals`, `resettable`
  (`'true'` или `'false'`). Они обновляются при изменении значения.
- Расширение отвечает bubbling composed-событиями: `mpu:slider-commit` с
  `detail: { value: number }` (значение ограничивается min/max) и `mpu:slider-reset` (только
  при `resettable` равном `'true'`).
- Одна точка обслуживает все слайдеры. `available(api, params)` может ограничить вклад по
  `label` или `unit`, чтобы слайдер «Скорость» отличался от «Потока».

#### Точки общей файловой таблицы

Файловая таблица (`plugins/shared/file-table`) собирается в каждый плагин, который её
встраивает, и обращается к хосту **от имени этого плагина**, поэтому три её точки объявляются в
манифесте каждого такого плагина (`fileTablePoints('<i18nPrefix>')` из
`plugins/shared/file-table/extension-points.ts` объявляет все три). Плагин, который их не
объявил, сохраняет штатное поведение. Сейчас их объявляют `@core/config` и `@core/jobs`.

- `file-actions` — обработчик получает контекст `{ root: string, path: string, isDir: boolean }`.
  Те же поля попадают в `available(api, params)` **строками** (`isDir` — `'true'` или
  `'false'`), поэтому расширение может ограничить свой пункт корнем или именем файла, например
  файлами `.cfg` в `config`. Пункты показываются после собственных пунктов плагина. Точка
  обслуживает все таблицы плагина, различать их позволяет `root`.
- `file-editor` — params `{ root, path, isDir, readonly }` (строки). Заменяет редактор,
  каким бы способом он ни открывался (клик по файлу или пункт «Редактировать»). Расширение само
  читает и сохраняет файл через свой api и по окончании сессии отправляет всплывающее
  (`bubbles`, `composed`) событие `mpu:editor-close`. Файловая таблица всё равно читает файл
  для своего редактора, поэтому, если `available` досчитается позже открытия, штатный редактор
  может на миг мелькнуть, прежде чем его заменит расширение.
- `file-viewer` — params `{ root, path, isDir }`; закрывается событием `mpu:viewer-close`.
  В остальном так же, как `file-editor`.
- Диалог вклада обязан жить в top layer браузера (`<dialog>.showModal()`), см. «Прочие правила».
