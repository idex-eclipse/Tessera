# GuardAgent: preflight-проверки запросов

Гард — декларативная проверка плагина, которая выполняется **перед** отправкой
`request()` другого плагина в Moonraker. Через гарды реализуют правила вида
«не стартовать печать, пока не подтверждены катушки» или «не выполнять
`SAVE_CONFIG` во время печати».

GuardAgent — инфраструктура хоста. Это **не шина**: плагины не обмениваются
сообщениями, агент только последовательно опрашивает гарды.

Границы механизма (важно понимать, чего он НЕ делает):

- Охраняется только `request()`. `subscribe()`, `onNotify()`, `poll()` и прямой
  HTTP (`httpBaseUrl`) — вне конвейера.
- Гарды покрывают только действия, сделанные **из этого UI**. Печать, начатую
  из другого клиента Moonraker, конвейер не видит. Для такого случая используйте
  реактивные плагины по состоянию принтера (подписались на `print_stats.state` и
  реагируете).
- Это **префлайт-проверка, а не граница безопасности.**
- Агент матчит только *строку метода*. Разбор параметров (например, какой
  именно G-code внутри `printer.gcode.script`) — работа обработчика гарда.
- Гарды **не меняют** запрос. Их три вердикта: `allow`, `deny`, `freeze`.

---

## Объявление гарда

В манифесте:

```json
{
  "guards": [
    {
      "id": "acme-print-check",
      "match": ["printer.print.start", "printer.gcode.script"],
      "handler": "printCheck"
    }
  ]
}
```

| Поле | Описание |
|---|---|
| `id` | идентификатор гарда внутри плагина (виден в атрибуции отказов) |
| `match` | список матчеров метода: точная строка или глоб с `*` |
| `handler` | имя **экспорта** entry-модуля с обработчиком |

Матчеры сравниваются с **именем метода** целиком. `*` — любая подстрока:

- `'printer.print.start'` — только этот метод;
- `'printer.*'` — все методы `printer.…`;
- `'server.files.*'` — все файловые;
- `'*'` — вообще любой запрос.

Параметры запроса в матчере не участвуют.

В модуле плагина:

```ts
import type { GuardDecision } from '@sdk/types';

export const printCheck = (
  request: { method: string; params: unknown; targetPrinterId: string },
  token: string,
  ctx: { targetPrinterId: string },
): GuardDecision | Promise<GuardDecision> => {
  if (request.method === 'printer.gcode.script') {
    const script = String((request.params as { script?: string })?.script ?? '');
    if (!/^\s*SAVE_CONFIG\b/i.test(script)) return { action: 'allow' };
  }
  return { action: 'deny', reasonKey: 'acme.guard.notNow' };
};
```

Если экспорт с именем `handler` отсутствует или не функция, гард пропускается
с предупреждением `[guard-agent] …: handler export "…" not found`.

## Вердикты

```ts
type GuardDecision =
  | { action: 'allow' }
  | { action: 'deny'; reasonKey?: string }
  | { action: 'freeze' };
```

| Вердикт | Что происходит |
|---|---|
| `allow` | цепочка идёт к следующему гарду; после последнего запрос уходит в прокси |
| `deny` | запрос немедленно отклоняется (`denied_by_guard` с вашим `pluginId`, `guardId`, `reasonKey`); остальные гарды не опрашиваются |
| `freeze` | запрос **паркуется**; плагин сам показывает свой оверлей и позже вызывает `api.guards.resume(token, …)` |

Обработчик может вернуть решение синхронно или через Promise.

> Верните **ровно** один из трёх объектов. Объект с неизвестным `action`
> воспринимается как `freeze` (запрос запаркуется и будет ждать `resume`
> до таймаута). Если обработчик вернул `undefined`/не объект, запрос
> отклоняется как `guard_timeout` без атрибуции.

### Ошибки обработчика

Исключение или reject Promise в обработчике трактуется как **`deny`**
(fail-closed): запрос отклоняется, ошибка пишется в консоль. Пишите обработчики
защитно.

## Freeze и resume

Пример «подтверждение перед стартом печати»:

```ts
let pendingToken: string | null = null;

export const printCheck = (request, token) => {
  if (request.method !== 'printer.print.start') return { action: 'allow' };
  pendingToken = token;           // запомнить ДО возврата решения
  showConfirmDialog(request);     // показать свой оверлей (overlays[] плагина)
  return { action: 'freeze' };
};

// когда пользователь нажал кнопку в оверлее:
function onUserDecision(ok: boolean) {
  if (!pendingToken) return;
  api.guards.resume(pendingToken, ok ? 'accept' : 'deny', ok ? undefined : 'acme.guard.cancelled');
  pendingToken = null;
}
```

- `token` приходит вторым аргументом обработчика — до решения. Он уникален для
  каждого запроса.
- `resume(token, 'accept')` продолжает обход **со следующего гарда** цепочки
  (диалоги нескольких гардов показываются строго по очереди); `'deny'` — отклоняет
  запрос с атрибуцией замораживавшего гарда.
- Показывает диалог **сам плагин** (обычно через собственный `overlays[]`):
  видимость оверлея — его решение.
- **Повторная отправка команды — не возобновление.** Это новая цепочка; идентичный
  запрос при живой парковке отклоняется как `already_pending`. Возобновление —
  только через токен.
- Неизвестный токен (повторный `resume`, просроченная парковка) игнорируется с
  предупреждением в консоли.

---

## Как строится цепочка

1. Берутся все гарды, чей матчер совпал с методом.
2. **Минус гарды плагина-инициатора** — гард не охраняет собственные запросы
   (защита от рекурсии).
3. Порядок = порядок регистрации: сначала core-плагины в порядке бандла, затем
   remote в порядке записей `mpu:v2:plugins`. Приоритетов нет.
4. Обход последовательный. Вето любого гарда побеждает (пересечение).

Практический вывод: вам не нужно (и не получится) «перехватить раньше всех».
Рассчитывайте, что другие гарды тоже отработают.

## Таймауты (fail-closed)

| Что | Лимит | Итог |
|---|---|---|
| Обработчик не вернул решение | 10 с | запрос отклоняется (`guard_timeout`) + уведомление |
| Парковка (`freeze`) без `resume` | 10 минут | запрос отклоняется (`guard_timeout`) + уведомление |

Если плагин с припаркованной цепочкой выключен или удалён — парковка
отклоняется (`denied_by_guard`).

## Что видит инициатор

`request()` отклоняется `GuardError` с полем `rejection`:

```ts
interface GuardRejection {
  code: 'denied_by_guard' | 'guard_timeout' | 'already_pending';
  guardId?: string;
  pluginId?: string;      // кто отклонил
  reasonKey?: string;     // i18n-ключ причины из deny/resume
}
```

Переводите `reasonKey` через `api.i18n.t`. Ключ должен быть в словаре того
плагина, который его назначил — или в общем (`common.*`), если хотите, чтобы он
был понятен любому инициатору.

## Уведомления

На вето, таймаут решения и таймаут парковки хост отправляет событие
`window` `mpu:guard-notify` (`detail`: `{ kind: 'denied' | 'decision_timeout' |
'park_timeout', pluginId, guardId, method, targetPrinterId, reasonKey? }`),
которое показывается в центре уведомлений. Это инфраструктурный транспорт, а не
канал для плагинов.

## Target-scoped гарды

Запрос знает принтера-адресата:

- `api.moonraker().request()` → активный принтер на момент вызова;
- `api.moonrakerFor(pid).request()` → `pid`.

Обработчик получает адресата в **третьем аргументе** `ctx.targetPrinterId` (и в
`request.targetPrinterId`). Ключ `already_pending` и парковки включают принтера:
заморозка на принтере A не блокирует тот же запрос на B.

Если гард хранит состояние (идёт ли печать, выполнен ли homing), держите его
**по принтерам** и **не завязывайте на жизненный цикл страницы или ядра хука**:
ядро данных создаётся лениво под потребителя и для принтера, на который идёт
запрос, может не существовать — гард увидит значения по умолчанию и решит неверно.
Надёжный приём — трекер уровня модуля, который запускает always-mounted
поверхность плагина (например, оверлей), а обработчик гарда при отсутствии данных
разово запрашивает их у Moonraker. Образец — `plugins/calibrations/printer-tracker.ts`.
Состояние держите так: `Map<printerId, State>`, подписываясь на все принтеры через
`moonrakerFor` и синхронизируясь с `onPrintersChange`. Гард, читающий состояние
только активного принтера, при вызове по неактивному (fleet) примет решение по
не тому принтеру.

---

## Наблюдаемость

Settings → About / Debug показывает зарегистрированные гарды (плагин, матчеры)
и припаркованные цепочки (токен-метод, кто заморозил, возраст) в реальном времени.

## Чего гарды не делают

- не меняют запрос и не подменяют параметры;
- не имеют приоритетов и переупорядочивания;
- не охраняют `subscribe`/`poll`/HTTP;
- не заменяют авторизацию Moonraker.
